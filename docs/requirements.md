# 세컨플래닝 고도화 요구사항 명세서

기준일: 2026-11-05 · 기준 브랜치: `dev-005-counselor-pagination` · 범위: Step 01 문서 수립

## 1. 문서 목적 및 적용 범위

본 문서는 최신 사용자 결정을 우선하여 운영 서비스의 기능과 권한을 정의한다. 레거시와 현재 코드는 근거와 비교 대상이며, 존재한다는 이유만으로 구현 의무가 생기지 않는다. 요구사항 확정 여부는 구현 완료 여부가 아니다. 상세 구현 현황은 향후 `docs/implementation-status.md`에서 관리한다. 이 문서는 구현이나 배포를 승인하지 않는다.

## 2. 서비스 개요

참여자가 상담 전 진단과 서비스 기대에 응답하고, 담당 상담사가 결과를 해석·안내한다. 허용된 참여자는 상담 후 진단과 만족도 설문에 응답한다. 관리자는 권한 범위의 운영과 통합 분석을 수행하고 고객사 담당자는 허용된 기업의 집계 현황을 확인한다.

## 3. 사용자 유형과 역할

- 참여자(P): 본인 계정으로 진단과 설문에 참여한다.
- 상담사(C): 본인에게 배정된 내담자를 관리하고 개인 결과를 상담에 활용한다.
- 관리자(A): 서버가 확인한 조직·업무 권한 범위에서 계정, 운영, 개인 보고서와 통합 분석을 관리한다.
- 고객사 담당자(M): 허용된 기업의 집계 현황을 확인한다.

개인 결과보고서는 한 내담자의 결과를 담으며 상담사용 5쪽과 내담자용 3쪽으로 구분한다. 통합 사전·사후 분석보고서는 권한 범위의 여러 참여자를 집계하는 관리자 전용 보고서다. 개인별 사전·사후 비교 화면은 이 둘과 구분하며 유지 여부가 미확정이다.

## 7. 결과 계산 및 보고서 정책

기존 점수 합산·환산·판정 경계, 최저 원점수 영역 선택과 동점 A>B>C>D>E, 연령대 및 13번 1순위 분류, 코멘트·키워드 무작위 선택과 결과 문구를 변경하지 않는다. 보고서를 열 때 판정은 현재 설정으로 재계산하며, 코멘트·키워드는 제출 시 저장한 `resultOf`를 사용한다. 상담사 응답 수정은 기존 재계산·결과 보존 규칙과 변경 이력을 따른다. 기존 특이점도 임의로 수정하지 않는다. 상세 계약은 `AGENTS.md`와 `docs/security-architecture.md` 9절이 기준이다.

개인 보고서의 상담사용 5쪽, 내담자용 3쪽을 유지한다. 내담자용이라는 명칭은 참여자의 직접 접근 권한을 뜻하지 않는다. 통합 보고서는 관리자 전용이며 개별 비교와 구분한다. 레거시 통합 화면은 9개(`RTABS`)이고 화면별 기준 모집단과 인쇄 범위를 표시한다. 사전·사후를 모두 완료한 참여자가 기본 모집단이고 만족도 화면은 그중 만족도 응답자를 사용하며, 첫 회기 기대는 사전 완료자를 사용한다. 기존 집계의 계산 방식도 임의로 바꾸지 않는다.

## 8. 데이터 저장·인증·권한 정책

운영에서는 인증된 신원과 서버 관리 역할·조직·담당 관계를 확인하고 RLS와 최소 권한을 적용한다. 클라이언트가 보낸 역할이나 ID는 권한 증거가 아니다. 개인 응답·결과·관계는 접근 통제된 DB에 보관하고 서버가 권한 범위 내에서 계산·집계하여 필요한 필드만 반환한다. 계산 엔진·판정 경계·비공개 비교 원본·전체 피드백과 매핑은 운영 브라우저와 API에 제공하지 않는다. 비밀번호 평문, 서버 키, 서비스 역할 키와 실개인정보를 저장소에 넣지 않는다. 감사 로그에 원문 응답·토큰·비밀번호를 남기지 않는다. 기존 개발 데모의 localStorage·데모 인증 및 브라우저 계산은 이행 예외이며 운영 보안 완료를 의미하지 않는다. 구체적 배포·키 관리 및 베타 게이트는 `docs/security-architecture.md`를 따른다.

## 9. 레거시 기능과 신규 요구사항의 관계

- 레거시 `vCounselor`는 담당 내담자의 통합 사전사후 보고서 메뉴를 제공한다. 최신 결정은 범위에 관계없이 상담사의 통합 보고서 생성·조회·관리를 금지하고 관리자에게만 부여한다.
- 레거시 개인 보고서의 별도 개인 비교와 `live/compare-view.js`의 담당 내담자 비교는 통합 보고서와 다르다. 유지·권한 변경·삭제는 결정되지 않았다.
- 레거시 통합 보고서 주석은 7개 화면이라 적지만 실제 `RTABS`와 `rp1`~`rp9`는 9개다. 실제 화면과 모집단을 분석 근거로 삼는다. PPT 다운로드는 `claude.use('downloads')` 환경 의존성이 있어 운영 출력 요구로 자동 확정하지 않는다.
- README의 과거 비공개 저장소 설명과 `docs/decisions.md`의 2026-10-27 공개 유지 결정이 충돌한다. 후자가 과거 결정을 대체한다. 공개 이력의 기존 로직은 이미 노출된 것으로 취급한다.
- 레거시 평문 데모 인증, 전역 데이터·브라우저 계산과 기존 동의 고지문은 운영 보안이나 법적 고지 확정의 근거가 아니다. `live/survey-view.js`도 고지 검토 필요를 표시한다. 최신 서버 권한 및 보안 정책이 우선한다.
- 사전·사후 보고서의 9개 분석 항목은 REQ-A-007~015로 정의한다. 그 밖의 레거시 메뉴·계정 방식·내보내기는 별도 결정 없이 구현 대상으로 확정하지 않는다.

## 10. 미확정 사항과 추가 의사결정 필요 항목

1. REQ-C-010 개인별 사전·사후 비교 화면의 유지 여부, 접근 역할·범위, 표시·출력 방식.
2. 상담사 응답 수정의 구체적 허용 필드·시점·승인 절차와 관리자 개인 보고서 관리의 세부 행위.
3. 조직·업무 권한의 세분화, 배정 변경·퇴사 시 접근 정책과 고객사 집계의 소수 집단 재식별 방지 기준.
4. 통합 보고서의 운영 출력 구성·전체/현재 화면 인쇄, PPT 제공 여부 및 자유 의견의 개인식별 방지·노출 방식. 레거시에서 코드로 표시해도 자유 서술 자체가 신원을 포함할 수 있다.
5. 개인정보 동의의 법정 고지 문구, 보관·삭제·백업·감사 보관 기간 및 동의 철회 처리.
6. 계정 발급·초기화·복구·강화 인증, 세션 정책과 참여자 안내 전달 방식.
7. 임시저장 충돌·재시도, 사후 허용 취소 여부, 사후 제출 후 수정 정책과 진단 단계·완료율 분모의 상세 정의.
8. 평가 설정 변경 시 과거 판정 정책과 코멘트·키워드 재추출 정책은 별도 결정 전 기존 동작 유지.
