# 단계 3a 결과: Vite 빌드·개발·preview 도입

## 무엇을 했나
- `vite.config.js`(저장소 루트): `root: src`, 진입점은 `src/index.html` 하나, `build.outDir: dist`. 복사 플러그인(`closeBundle`에서 `src/js`, `src/data`를 `dist`로 그대로 복사)이 일반 `<script src>` 문제를 해결한다. **파일 이동 없음**(`tests/split`, `CLAUDE.md`의 경로 유지). 이 설정 파일은 `vite`를 import하지 않으며 의존성은 `vite@5.4.21` 하나뿐이다.
- 앱 코드·CSS·화면·표지 이미지는 그대로다(인라인 `<style>` 유지, 표지 base64 유지).
- 개발 서버·preview의 `/counselor` → `/counselor/` 리다이렉트는 진입점이 하나뿐이라 만들지 않았다(3c).

## 스크립트
| 명령 | 내용 |
|---|---|
| `npm run dev` | `vite` 개발 서버(src를 그대로 서빙. 개발 서버는 HTML에 클라이언트 스크립트를 주입하므로 정답표 대조 대상이 아니다) |
| `npm run build` | `vite build` → `dist/` |
| `npm run preview` | `vite preview`(dist 서빙) |
| `npm run test:dist` | 빌드 → `dist`와 `src` 바이트 비교(`tests/tools/check-dist.mjs`) → preview 기동 → `TARGET_URL`로 전체 테스트 → preview 종료. `-- --visual`이면 캡처 비교(252장). 비동기 spawn, 제한 시간: 빌드 90초·점검 30초·기동 30초·테스트 300초 |
| `npm run test:minmut` | 최소 변조 시험 6건(`docs/변조-시험-최소-실행기.md`) |

## 확인 결과
- `dist`는 9개 파일(`index.html`, `js/` 6개, `data/` 2개)이고 **`src`와 바이트 동일 9/9**. 번들 산출물 등 예상 밖 파일은 없다.
- `npm run test:dist`: 골든·계약·defs·스냅샷(HTML·JSON·인쇄·CSS 지문)·e2e **108건 통과**, 건너뜀 2건(1a 전용 분할 증명). 정답표 변경 없음.
- `npm run test:dist -- --visual`: 캡처 **252장 통과**.
- 실행 후 preview 서버·브라우저 프로세스가 남지 않음을 확인.

## 추가 점검(읽기 전용): 테스트가 실행하지 않는 함수 32개 중 클릭 경로에 있는 것
3a-0 프로브에서 테스트가 한 번도 실행하지 않은 최상위 함수가 32개였다. 이 중 인라인 핸들러(`onclick` 등)와 관련된 것을 가렸다. 3b에서 핸들러를 `window`에 등록하는 호환 레이어를 둘 때, 이 함수들의 등록 누락은 **어떤 테스트도 잡지 못하고 클릭하는 순간에야 `ReferenceError`로 드러난다.**

**핸들러 속성이 직접 호출하는 23개** (속성 수 · 이벤트 · 들어 있는 화면 함수)
| 함수 | 속성 | 이벤트 | 화면 함수 |
|---|---|---|---|
| `copyText` | 4 | onclick | `editPanel`, `part1`, `cnsReg` 외 1 |
| `goHome` | 2 | onclick | 정적 헤더, `vForm` |
| `a2Hint` | 1 | oninput | `wConsent` |
| `goQ` | 1 | onclick | `wReview` |
| `cancelEdit` | 1 | onclick | `wReview` |
| `goEp` | 3 | onclick | `part1` |
| `goReg` | 1 | onclick | `part1` |
| `delEnt` | 1 | onclick | `part1` |
| `delCons` | 1 | onclick | `part1` |
| `readCsv` | 2 | onchange | `part1`, `cnsReg` |
| `setLogo` | 1 | onchange | `part1` |
| `clearLogo` | 1 | onclick | `part1` |
| `previewReport` | 2 | onclick | `part1` |
| `msgOf` | 2 | onclick | `part1`, `cnsReg` |
| `copyLink` | 2 | onclick | `part2` |
| `setFc`, `setFs`, `setFq` | 각 1 | onchange | `part2` |
| `goPage` | 5 | onclick | `part2` |

| `mgrMsg` | 1 | onclick | `mgrSection` |

**핸들러가 부르는 함수 안에서 간접 호출되는 3개**: `abortEdit`(`cancelEdit`·`setMode`에서), `loadPptx`·`buildPptx`(`exportPptx`에서).

**핸들러 경로가 아닌 6개**: `inp`, `sel`(렌더 보조), `selEtc`, `wDiag_pre_unused`, `vForm`, `vForm_disabled`(죽은 코드로 보이는 것 포함).

- 관리자 화면(`part1`, `mgrSection`)과 상담사·관리자 공유 화면(`part2`, `aReport`, `cnsReg`)에 집중돼 있다. 이 화면들의 핸들러는 스냅샷 HTML에는 문자열로 있지만 **클릭하는 e2e가 없다.**
- 3b에서의 대책 제안: 핸들러 등록 검사(스냅샷 HTML에서 호출 이름을 추출해 `window` 등록 여부 확인)에 더해, 위 23개를 직접 클릭·변경하는 최소 e2e를 3b-2의 해당 묶음(관리자, 상담사·공유)에 추가한다. 이는 테스트 추가이며 정답표는 바꾸지 않는다.
