# 첫 세션 지시문 (단계 0만)

아래를 Claude Code에 그대로 붙여 넣는다.

---
이 저장소의 `CLAUDE.md` 와 `docs/decisions.md` 를 먼저 읽어라. 이번 세션은 단계 0(안전망) 하나만 한다. 앱 코드는 한 줄도 수정하지 않는다.

## 목적
이후 단계에서 계산 결과와 화면이 전혀 바뀌지 않았음을 증명할 기준선을 만든다. 기준은 `legacy/index.original.html` 이다.

## 할 일
1. 저장소 준비
   - `git init`, 첫 커밋(파일 구성 그대로).
   - `legacy/SHA256.txt` 와 `legacy/index.original.html` 의 해시가 같은지 확인한다. 다르면 멈추고 보고한다.
2. 도구 설치: 테스트용 `playwright` 와 테스트 러너만 devDependency로 추가해도 된다(이 지시로 승인). 그 밖의 의존성은 먼저 묻는다.
3. 골든 정답표 생성기 (`tests/golden/`)
   - legacy 파일을 헤드리스 브라우저로 열고, 전역 함수·상수를 `page.evaluate` 로 직접 호출한다.
   - 포함할 것:
     - 영역별 원점수 3~15에 대한 환산값과 판정(5영역 × 13)
     - 코멘트 대상 영역 선택: 다섯 영역의 원점수 조합 전수(13의 5제곱 = 371,293가지). 함수가 영역별 합계만 쓰므로 합계를 만드는 대표 응답 배열을 쓴다.
     - `computeResult` 의 무작위 선택: `pick` 함수를 주입해 호출 순서를 기록하고, 코멘트 3 × 연령대 키워드 3 × 경력목표 키워드 3 × 예언 키워드 9 조합을 전부 돌린다. 연령대(5) × 13번 1순위(7) × 코멘트 영역(5)과 곱해 약 42,000건이다. 너무 오래 걸리면 줄이되 줄였다는 사실과 기준을 보고한다.
     - 연령대 경계(29/30, 39/40, 49/50, 59/60세 전후)와 13번 1순위의 키워드 분류
     - 자체 검증 탭(관리자 → 원본 대조 검증)의 항목별 결과 전체
   - 결과는 JSON 파일로 저장한다. 이후 단계에서 같은 입력으로 새 코드를 돌려 이 파일과 한 건도 다르지 않아야 통과한다.
4. 화면 기준선
   - 화면 HTML 스냅샷과 캡처를 만들려면 결과가 매번 같아야 한다. 먼저 시드 데이터와 화면이 난수·현재 시각을 쓰는지 조사해 보고하고, 쓰면 초기화 스크립트로 `Date` 와 난수를 고정한다.
   - 대상 화면: 참여자(로그인, 홈, 설문 5단계, 제출 완료, 사후 진단·만족도), 상담사(탭 3개), 관리자(탭 4개), 고객사(로그인, 대시보드), 결과 보고서 3쪽·5쪽, 사전사후 보고서 9개 화면.
   - 캡처: 너비 375·768·1100 × 라이트·다크.
   - 인쇄 PDF 쪽수: 내담자용 3쪽, 상담사용 5쪽(Chromium, 인쇄 축소 `fitSheets` 적용 상태).
5. 역할별 흐름 e2e (새로 작성)
   - 관리자가 기업·상담사·내담자·고객사 담당자를 등록한다 → 내담자가 초대 링크로 들어와 36문항을 제출한다 → 제출 후 결과가 보이지 않고 수정이 잠긴다 → 상담사가 자기 내담자만 보고 응답을 수정해 이력이 남는다 → 고객사 담당자가 집계만 본다 → 사후 진단·만족도 → 사전사후 보고서가 열린다.
   - PPT 내보내기는 알려진 제한이므로 제외한다.
6. `package.json` 에 실행 스크립트(골든, 스냅샷, e2e)를 만들고, `CLAUDE.md` 의 "테스트 실행" 칸을 채운다.
7. 커밋하고 멈춘다.

## 하지 말 것
- `legacy/` 와 `src/` 의 앱 코드 수정, 구조 변경, 파일 삭제.
- 단계 1 이후 작업 시작.
- 확인하지 않은 항목을 통과했다고 보고하는 것.
