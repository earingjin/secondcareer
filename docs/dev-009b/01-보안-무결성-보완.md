# DEV-009B-1 사후진단 DB·서버 보안 및 무결성 보완

기준: `19a2dd5` → 이번 커밋. 위험 ID는 [`docs/dev-009a/02-DB-계약-위험.md`](../dev-009a/02-DB-계약-위험.md)를 따른다.
**SQL 실행, DB 접속, 배포는 하지 않았다.** 아래 SQL 은 모두 미적용 제안이며 PostgreSQL 에서 파싱되지 않았다.

## 1. 수정 사항 (전 → 후)

| R-E1 | 사후 초안: 사전 제출 확인과 쓰기가 별도 요청(비원자) | 초안 저장을 새 RPC `secondcareer_post_draft_v1` 로 이동. 권한·사전 제출·버전·쓰기·이력을 한 트랜잭션에서 처리. 초안·제출이 같은 참여자 단위 advisory lock(`':post'`)으로 직렬화되어 첫 행 동시 생성도 DB 가 순서를 정한다 | `post-draft.sql`(신규), `index.ts` |
| R-E2 | 사후 초안 이력 없음 | 초안 저장마다 `action='post-draft'` 이력(사전 초안과 같은 정책) | `post-draft.sql` |
| R-P1 | 운영 카탈로그 대조에서 발견한 권한 위험 | 최소 권한 변경안 작성(권장안 + 대안). **세부 내용은 Git 제외 로컬 파일**(`supabase/proposals/*.local.sql`)에만 둔다 | 비공개 |

유지한 것: 사전진단(`write_v1`)·계산식·보고서·상담사 조회·비교 API, 응답 형식, `postTestGate=false`, 서버 플래그 정책. 브라우저 코드는 바꾸지 않았다.

잠금 순서: 사전 저장(`write_v1`)은 `':pre'` advisory lock → 사전 행 `FOR UPDATE`. 사후 함수는 `':post'` advisory lock → 사전 행 `FOR SHARE` → 사후 행 `FOR UPDATE`. 서로 상대의 advisory 키를 잡지 않으므로 순환 대기는 없다고 판단한다 **[추론, 실제 DB 미검증]**.

## 2. 테스트 결과 (로컬)
- `npx playwright test tests/live/post-draft-server.spec.mjs`: 20건 통과(신규 3건: 초안 RPC 호출·행위자·이력, 초안 RPC 오류·미확인 응답 매핑, 버전 문자열 형식 차이).
  - 기존 제출 오류 매핑 테스트에 22023→400, 23505→409 를 추가했다.
  - 제출 모형에 DB 측 역할·조직 검사를 반영했다.
  - 이전 초안 테스트의 "RPC 0회" 단정은 "사전 RPC(`write_v1`) 미호출"로 바꿨다. 초안이 이제 RPC 를 쓰기 때문이다.
- 변조 1건: 버전 비교를 문자열 비교로 되돌리면 신규 테스트가 실패했고, 원상 복구했다.
- 전체 `npx playwright test`: 243건 통과, 실패 0, skip 5(기존과 같음).
- **주의:** 서버 테스트의 DB·RPC 는 SQL 을 흉내 낸 JavaScript 모형이다. SQL 문법, 잠금, 트랜잭션, RLS, 권한은 이 테스트로 검증되지 않는다.

## 3. 미검증 위험
1. 두 SQL 의 PostgreSQL 파싱·실행(문법 오류 가능성 포함), `#variable_conflict use_variable` 하의 이름 해석.
2. 실제 동시성: advisory lock 직렬화, 사전 행 `FOR SHARE` 와 상담사 사전 수정의 상호작용, 교착 여부.
3. `timestamptz` 의 jsonb·Data API 직렬화 형식과 밀리초 절사 후 버전 왕복.
4. R-P1 변경 후 Edge Function(`service_role`) 경로·참여자 경로의 회귀 여부, 다른 소비자(대시보드 등)가 직접 조회를 쓰는지.
5. 초안마다 이력을 남기면서 생기는 이력 행 증가량(자동 저장 0.7초 디바운스).
6. 운영에 배포된 Edge Function 코드와 저장소 코드의 일치 여부.
7. 새 Edge Function 은 `secondcareer_post_draft_v1` 이 없는 DB 에서는 사후 초안 저장이 500 이 된다. 서버 플래그가 꺼져 있어 운영 영향은 없지만, **SQL 적용 전에 함수를 배포하고 플래그를 켜면 안 된다.**
