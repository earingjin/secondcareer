# 단계 3b 지시서 (작업 도구 전환용 인수인계)

이 문서는 도구를 바꿔도 같은 기준으로 작업하도록, 대화에만 있던 결정과 요구사항을 저장소에 남기는 용도다.
규칙의 원본은 `AGENTS.md`이고, 결정 이력은 `docs/decisions.md`에 있다.

## 1. 현재 상태
아래 3a 상태는 도구 전환 당시 기록이다. 2026-10-27 기준 3b-1은 로컬 커밋 `73930653e92e50e341870877f02d13ed5c78d8c2`에서 완료됐다(커밋 2 변경 불필요). ESM 번들 전환으로 현재 `dist`는 src 바이트 복사본이 아니다. 마지막 검증 기록: HTTP/배포 각각 111 통과·2 건너뜀, 시각 비교 252장 통과. 이는 기능 회귀 기록이며 운영 보안 검증은 아니다.

- 완료: 단계 0, 1a, 1b, 2a, 2b, 2c, 3a-0, 3a (태그 `step-1a` … `step-3a`). 마지막 태그는 `step-3a`.
- `dist`는 `src`와 바이트 단위로 같다. `npm run test:dist` 108건 통과(1a 전용 2건 건너뜀), `npm run test:dist -- --visual` 캡처 252장 통과.
- 스택: 프런트 Vite 멀티페이지(문자열 템플릿 유지), 백엔드 Supabase. 계산 로직과 디자인은 바꾸지 않는다.
- 로컬에만 있는 것: 캡처 기준선 이미지(`tests/snapshot/baseline/img`), `node_modules`. 같은 폴더에서 계속 작업해야 캡처 비교를 쓸 수 있다.

## 2. 도구 전환 규칙
- 한 번에 한 도구만 같은 폴더에서 작업한다. 전환 전에 `git status`가 깨끗하고 커밋·태그가 끝나 있어야 한다.
- 도구가 바뀌어도 단계 하나 끝날 때마다 보고하고 멈춘다. 정답표 폴더(`tests/golden`, `tests/contract`, `tests/snapshot`)의 diff는 비어 있어야 하며, 있으면 이유와 승인 여부를 보고한다.
- 모든 명령에 제한 시간을 두고, 5분 넘을 것 같으면 예상 시간을 먼저 보고한다. 백그라운드로 돌려 놓고 기다리지 않는다.

## 4. 단계 3b·3c 설계에 반드시 반영할 요구사항
### 3b-2 이전 보안 설계 확정
- 정책 원본은 [security-architecture.md](security-architecture.md)다. 공개 저장소 유지와 기존 엔진 공개 위험을 인정하고, 신규 비밀·개인정보·기밀 서버 원본을 커밋하지 않는다.
- 3b-2·3c는 기능 보존을 위한 구조 분리이며 최종 보안 조치가 아니다. 폴더·번들·역할별 URL·전역 노출 제한은 인증·업무 권한 검증을 대신하지 않는다.
- 최종 운영은 모든 역할에 대해 계산·평가 원본·전체 피드백을 브라우저에 제공하지 않는다. 서버 전용 구현과 데이터의 비공개 저장·배포 경로는 단계 7 전에 별도 승인한다.

### 3b-1 (구현 전에 설계 보고, 승인 후 구현)
- classic 인라인 스크립트는 `type=module`보다 먼저 실행된다. core를 모듈로 바꾸면 인라인 코드가 core 전역을 못 찾는다. 실행 순서를 어떻게 보장하는지 설계에 명시한다. 전역 노출 어댑터가 필요하면 3b-2가 아니라 3b-1에 둔다.
- core는 화면·`window`·`localStorage`·DOM에 의존하지 않는다(서버 함수에서 재사용하기 위함). 분리 대상: `resultOf`의 `save()`, `recomputeResult`의 `COUNSELORS`·`new Date()`, `toast`·`copyText`·`$`·`esc`의 DOM 의존.
- 재대입되는 `let`(`DB`, `ENT`, `COUNSELORS`)과 같은 객체여야 하는 `S`의 처리 방식을 정한다.
- 테스트가 접근하는 전역 82개(+`window.SecondPlanning`)는 정답표를 바꾸지 않고 접근할 수 있게 어댑터를 둔다(`docs/단계3-전역-핸들러-조사.md`).
- strict 프로브: 정적 점검 0건, 106건 통과. 단 테스트가 실행하지 않는 함수 32개는 동적으로 확인되지 않았다(`docs/단계3a-결과.md`).

### 3b-2 (묶음별로 쪼개 매번 전체 테스트와 커밋)
순서: 상태·UI → 설문 → 보고서·상담사/관리자 공유 → 관리자 → 상담사·고객사·참여자.
- 기존 클라이언트 엔진·테스트 전역 연결은 기능 보존용 이행 예외로만 유지한다. 신규 서버 전용 로직·비공개 설정/문구 원본을 UI·shared·역할 번들에 추가하지 않는다. 기존 노출을 보안 완료로 보고하지 않는다.
- 계산·판정·문구·난수·저장·참조·리포트와 기준선을 보존한다. 서버 이전이나 보안 수정은 승인된 후속 범위에서 수행한다. 정책 충돌이 생기면 구현 전에 보고한다.
- 인라인 핸들러 속성 101개는 출력 HTML이 한 글자도 바뀌면 안 되므로, 진입점마다 필요한 핸들러만 `window`에 등록하는 호환 레이어를 쓴다. 이벤트 위임으로 바꾸지 않는다.
- 테스트가 실행하지 않는데 클릭으로 호출되는 함수 23개(목록은 `docs/단계3a-결과.md`)는 해당 묶음에서 직접 클릭·변경하는 최소 e2e를 정답표 변경 없이 추가한다.

### 3c
- CSS는 `public/css/app.css`에 원문 그대로 둔다(Vite의 CSS 처리는 규칙을 바꾼다). 외부 CSS가 인쇄(`page.pdf`)와 캡처 타이밍(스타일 로드 전 출력)에 주는 영향을 검증 항목에 넣는다.
- `/counselor` → `/counselor/` 재작성이 dev·preview·배포 호스트에 필요하다. 배포 호스트는 아직 미정이며, 선택 기준으로 `docs/decisions.md`에 기록한다.
- 역할 전환 버튼: 데모 빌드는 현재 헤더 HTML 그대로(기준선 유지), 운영 빌드는 제거. 운영 헤더 기준선은 기획자가 캡처를 눈으로 확인한 뒤에 확정한다.
- `mgrMsg`의 `#client` 링크: 새 구조에서 동작하는 방식을 설계 보고에 포함한다(예: `/`에서 `#client`이면 `/manager/`로 이동). 링크 정책은 별도 판단 목록에 있다.
- `window.SecondPlanning`은 상담사·관리자 진입점과 테스트용 합성 진입점에만 노출한다. 참여자·고객사에는 노출하지 않는다.
- 진입점 분리는 코드 구성일 뿐 접근 통제가 아니다. 모든 데이터(평문 비밀번호 포함)가 같은 오리진의 localStorage에 있어 개발자도구로 읽을 수 있다. 실제 분리는 단계 7.

### 단계 7 및 베타 배포 필수 조건
- 인증된 사용자 신원과 서버 관리 역할·담당·소속 관계를 확인하고 RLS·최소 권한을 적용한다. 브라우저가 보낸 역할·상담사 코드·참가자 ID는 권한 증거가 아니다.
- `computeResult`·`resolveResult`·`recomputeResultCore`, 환산·판정, 평가/비교 원본과 전체 피드백 매핑은 서버 전용으로 실행·보관한다. 운영 브라우저는 권한별 최소 응답만 렌더링한다. 평문 비밀번호 저장과 서버 키의 클라이언트 노출을 금지한다.
- 개발 프로토타입·데모/회귀 전역과 최종 운영 산출물을 분리한다. 3c의 “운영 빌드”는 역할별 UI 명칭이며 단계 7 보안 게이트 전에는 실데이터·실계정 베타로 사용할 수 없다.
- 베타 전 `security-architecture.md` 11절의 역할별 API/RLS·직접 URL·개발자 도구·자산/소스맵·비밀정보·개인정보/감사·동시성 검증과 기존 계산·보고서 회귀를 모두 통과하고 사용자의 배포 승인을 받는다. 미검증·실패 시 배포하지 않는다.

## 5. 테스트 명령
- `npm test`: legacy 대상 (기준 파일 확인용)
- `npm run test:src`: 과거 file:// 기반 명령(현재 ESM에는 부적합). 소스는 `npm.cmd run test:url -- --root src`로 HTTP 검증한다.
- `npm run test:dist`: 빌드 후 preview로 전체 테스트. `-- --visual`을 붙이면 캡처 비교
- `npm run test:minmut`: 최소 변조 시험(테스트 도구나 정답표 생성 방식이 바뀔 때만, `docs/변조-시험-최소-실행기.md`)
- 순수 이동 단계의 증거는 정답표 통과다. 변조 시험을 단계마다 하지 않는다.

```
AGENTS.md, docs/단계3b-지시서.md, docs/decisions.md, docs/단계3a-결과.md, docs/단계3-전역-핸들러-조사.md를 읽어라. 이 세션은 단계 3b-1의 설계 보고까지만 한다. 구현하지 마라.

1. 먼저 AGENTS.md의 절대 규칙을 네 줄 이내로 요약해 보여주고, 내 승인 후 진행하라.
2. 환경 점검: Node 버전(.nvmrc), `npm ci`, `npm run test:dist`를 실행해 건수를 보고하라(기대: 108건 통과, 2건 건너뜀). 실패하거나 샌드박스·권한 때문에 실행이 막히면 우회하지 말고 원인을 보고하라. 한글 경로와 로컬 서버·브라우저 실행이 막히는지 포함한다.
3. 점검이 통과하면 3b-1 설계를 보고하라. 포함: core 모듈의 구성과 파일 목록, 실행 순서 보장 방식, 전역 노출 어댑터의 위치와 대상 이름, 부수 효과 분리 목록(resultOf의 save, recomputeResult, toast, copyText, $, esc), let 재대입 처리, 테스트 어댑터, 단계 분할과 롤백, 위험 목록과 확인하지 못한 것.

금지: legacy/ 수정, 정답표 수정, CSS 변경, 계산 로직 변경, 요청 외 구조 변경.
```
