# 단계 3a-0 프로브 결과 (읽기 전용, 2026-10-26)

저장소는 바꾸지 않고 임시 복사본·저장소 밖 설정으로 확인했다. 스크립트는 저장소에 두지 않았다.

## 1. 한글 경로에서 vite build / preview
- 저장소 실경로(한글 포함)를 `root`로 지정한 설정(저장소 밖)으로 `vite build`: **성공**(종료코드 0, 1.3초). 한글 경로가 원인인 오류는 없었다.
- 일반 `<script src>`는 Vite가 번들하지 않고(경고 8개) 복사도 하지 않는다. **의존성 없는 복사 플러그인**(`closeBundle`에서 `src/js`, `src/data`를 outDir로 복사)으로 해결됐다. dist에는 `index.html`과 js 6개·data 2개가 모두 들어갔다. 즉 `src/js`·`src/data` **이동 없이** 가능하다(결정 2).
- `dist/index.html`은 `src/index.html`과 문자열이 같았다(인라인 `<style>`·`<script>` 변형 없음).
- `vite preview`: `/`, `/js/…`, `/data/…` 모두 200. 이 preview를 `TARGET_URL`로 골든·계약 테스트를 실행해 **25건 통과**.
- 참고: 진입점이 1개뿐인 프로브라 `/counselor`·`/counselor/`는 404였다(진입점 폴더가 없음). 끝 슬래시 없는 경로 404는 설계 단계 실험에서 확인한 사실이다.

## 2. strict 모드(`"use strict"`) 프로브
복사본의 일반 스크립트 8개 첫 줄과 인라인 `<script>` 태그 줄에 `"use strict";`만 삽입(줄 번호 불변).
- **컴파일(조기 오류)**: 9개 스크립트 모두 통과. 8진 리터럴·`with`·`arguments.callee` 등 strict 금지 구문 없음(8진 리터럴 grep 3건은 `'010-1111-2222'` 같은 문자열 속 숫자의 오탐).
- **전체 테스트 실행**: HTTP 대상으로 골든·계약·스냅샷·e2e **106건 통과, 실패 0, 페이지 오류 0건**.
- **테스트가 실행하지 않는 함수 32개**(커버리지): `copyText`, `goHome`, `inp`, `selEtc`, `sel`, `a2Hint`, `goQ`, `wDiag_pre_unused`, `vForm`, `vForm_disabled`, `abortEdit`, `cancelEdit`, `goEp`, `goReg`, `delEnt`, `delCons`, `readCsv`, `setLogo`, `clearLogo`, `previewReport`, `msgOf`, `copyLink`, `setFc`, `setFs`, `setFq`, `goPage`, `loadPptx`, `exportPptx`, `buildPptx`, `mgrMsg`, `reissueMgr`, `delMgr`. 이 함수들 안의 strict 위반은 테스트로 드러나지 않는다.
- **전체 소스 정적 점검**(문자열·주석을 걷어낸 코드에서 선언 없이 대입하는 식별자 찾기): **후보 0개**. 일부러 넣은 위반 2곳은 정확히 감지했다(감지 능력 확인). 쉼표로 이어진 선언·매개변수·구조 분해는 선언으로 인정했다.
- **결론**: 깨지는 지점은 발견되지 않았다. 단, 테스트가 실행하지 않는 32개 함수에는 동적 확인이 없다(정적 점검 0건에 의존). 모듈 변환 시 `this`·`const`의 `window` 속성 부재·재대입 `let`은 strict와 별개의 위험이며 설계 보고서에 있다.

## 3. 하네스 변경 확인용 최소 변조 시험 (6건)
변조한 복사본을 정적 서버로 서빙하고 `TARGET_URL`로 지정 테스트만 실행(비동기 spawn, 변형당 3분 제한, 첫 실패 시 중단).

| # | 변조 | 지정 테스트 | 판정 | 소요 |
|---|---|---|---|---|
| 1 | 판정 경계 7→8 | 골든 `환산·판정` | 잡힘 | 4.3초(첫 변형) |
| 2 | 문항 문구 1글자 | 계약 `문항 정의 덤프` | 잡힘 | 2.2초 |
| 3 | 로그인 제목 문구 | 스냅샷 `p-login` | 잡힘 | 2.0초 |
| 4 | CSS 색 1단계 | `CSS 규칙 지문` | 잡힘 | 2.1초 |
| 5 | 제출 후 수정 잠금 해제 | e2e 3단계(앞의 1·2단계는 선행 조건) | 잡힘 | 15.7초 |
| 6 | 대상 확인 | 골든 `환산·판정`을 원본 서버에 실행 | 원본 서버 통과 + 변조 서버(1번) 실패 → 잡힘 | 4.4초 |

- 5번은 처음에 `-g` 패턴의 백슬래시가 셸에서 깨져 테스트가 선택되지 않아 "오류"였고(합격으로 세지 않음), 패턴을 고쳐 다시 실행해 "잡힘"이 됐다.
- 앞서 시도한 44건 스위트는 같은 프로세스의 서버를 `spawnSync`가 막는 결함으로 시간 초과가 났고 취소했다(저장소에 포함하지 않음).
